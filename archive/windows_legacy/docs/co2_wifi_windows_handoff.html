CO2_WIFI：Windows Platform Handoff

從 MacBook 離開後，在 Windows 使用 Dropbox 同步的既有 CO2_WIFI 專案續接。此文件不建立新 project，也不假設 MacBook 本機 chat 會同步。

續接流程

01Windows 啟動 Codex
→
02建立 New Chat
→
03Open existing folder
→
04選 Dropbox CO2_WIFI
→
05確認 working directory
→
06先讀交接 MD

操作步驟

  1. 先等待 Dropbox 在 Windows 同步完成，確認專案含有 AGENTS.md、HANDOFF.md、src/、docs/。
  2. 開啟 Windows Codex，選擇 New Chat。
  3. 選擇 Open existing folder，不是 Build New Project。
  4. 選擇 Dropbox 同步後的 codex_on_CO2_WIFI_project 資料夾。
  5. 在 Windows Terminal 確認目前 working directory，例如：
cd C:\Users\<WindowsUser>\Dropbox\0DownLoad\codex_on_CO2_WIFI_project
pwd
正確結果：顯示 Windows 的專案路徑。它不會與 Mac 的 /Users/... 相同，但最後資料夾必須是 codex_on_CO2_WIFI_project。

第一段交接提示

這是既有 Dropbox 同步專案，不要建立新 project。
請確認目前 working directory 是 codex_on_CO2_WIFI_project。
先讀取 AGENTS.md、HANDOFF.md、docs/qa_co2_progress_daily_digest.html。
先摘要目前版本、已驗證事項、未完成項目與 Windows 下一步；
不要修改檔案，等待我說 go。

文件角色

文件Windows 新 task 可取得的內容
AGENTS.md專案規則、QA 記錄方式、驗證與交接要求。
HANDOFF.md最新版本、Gateway/Bridge 架構、T1–T5 LED 實測、Windows bridge 下一步。
docs/qa_co2_progress_daily_digest.html已驗證設計、RCA、時間序與下一步證據。
限制：Windows New Chat 不會自動取得 MacBook 本機 task 的逐字 chat、Terminal 畫面、USB serial port 或正在運行的 bridge process。重要工程結論以 Markdown 與 QA Digest 為準。

Windows Bridge（需要時）

先閱讀 platform/windows/README.md，再執行：

py -3 -m pip install --user paho-mqtt
powershell -ExecutionPolicy Bypass -File .\tools\windows\start_mqtt_bridge.ps1
curl http://127.0.0.1:8080/api/co2

以 Windows Wi-Fi IPv4 重新產生 QR，保存於 offline_qr/windows/，確認後複製至 offline_qr/current/。
